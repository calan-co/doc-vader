## Statement

As a maintainer, I want a defined cross-file registry model and representative fixtures so that graph and naming rules have a stable contract before implementation starts.

## Context

The graph and naming feature depends on shared resolution semantics across backlog items, documentation files, and cross-references. The codebase does not yet have an agreed registry abstraction or test fixture set for those behaviors.

## Goals

- Define the registry interface and expected lookup behavior
- Document cache, invalidation, and error-reporting expectations
- Create fixtures covering normal and failure cases used by future plugin tests

## Deliverables

- Registry model document covering inputs, outputs, and lifecycle
- Fixture set for successful references, missing targets, cycles, and duplicate names
- Implementation notes identifying the expected integration points for Epic 170 Track C

## Tasks

1. Define the registry entities and lookup rules
2. Document failure modes and trace output expectations
3. Create reusable fixtures for graph and naming validation tests
4. Link the design to the Epic 170 Track C implementation work

## Acceptance Criteria

- [ ] Registry interface and resolution semantics are documented
- [ ] Fixture set covers normal, missing-target, duplicate, and cyclic cases
- [ ] Integration points for Track C are identified with no unresolved blockers
