## Problem

Current sweep integrations reuse `backlog ingest-event` by constructing synthetic `pull_request.closed`
payloads and injecting work-item identity tokens into freeform text fields.  This adapter is fragile:
any change to the extractor regex silently breaks sweep.  The root issue is that sweep already knows
exactly which work-items to act on — it should not need to re-encode that knowledge as freeform text.

## Goal

Add a `doc-vader work-item` sub-command namespace with atomic, explicit-subject mutations that:

- accept work-item identity directly (no payload synthesis, no regex extraction)
- reuse the same engine functions (`linkWorkItem`, `recordWorkItemCommit`, `finalizeWorkItem`)
- share the single policy evaluator introduced in story 225 for readiness/finalization checks
- allow sweep to be rewritten as a sequence of direct CLI calls

## Proposed Command Family

### `doc-vader work-item link`

Link a pull-request URL to a work item.

```sh
doc-vader work-item link \
  --id work-item:022 \
  --pr <url>
```

Idempotent — safe to call again if the URL is already recorded.

---

### `doc-vader work-item record-commit`

Record a merge commit against a work item.

```sh
doc-vader work-item record-commit \
  --id work-item:022 \
  --sha <merge-commit-sha> \
  --summary "feat: ..."
```

---

### `doc-vader work-item refresh-state`

Re-evaluate a work item against the finalization policy (enforcing the all-linked-PRs-merged
constraint from story 225) and advance its status if ready.

```sh
doc-vader work-item refresh-state \
  --id work-item:022 \
  [--provider github] \
  [--dry-run]
```

Outputs: current status, policy verdict (ready/blocked), and blocking reason if applicable.

---

### `doc-vader work-item finalize`

Finalize a work item that already satisfies all policy conditions, moving it to the archive.

```sh
doc-vader work-item finalize \
  --id work-item:022 \
  [--dry-run]
```

Fails explicitly if the policy evaluator reports the item is not ready.

---

## Namespace Separation

- `doc-vader work-item` — atomic, explicit-subject mutations (this story)
- `doc-vader backlog` — orchestration and discovery (sweep, scan, validate)

The sweep workflow is rewritten to:

1. discover eligible work items via `backlog` commands
2. call `work-item link`, `work-item record-commit`, `work-item refresh-state` per item
3. call `work-item finalize` for items that pass policy

No synthetic payloads at any step.

## Acceptance Criteria

- [ ] `doc-vader work-item link`, `record-commit`, `refresh-state`, and `finalize` commands exist.
- [ ] Each command accepts `--id` as explicit work-item identity; no payload text extraction occurs.
- [ ] `refresh-state` applies the all-linked-PRs-merged policy from story 225.
- [ ] `finalize` fails with a clear error if the policy evaluator reports not-ready.
- [ ] All four commands support `--dry-run`; output lists per-item actions and blocked reasons.
- [ ] Sweep workflow is rewritten to use `work-item` commands; synthetic payload construction removed.
- [ ] Existing `ingest-event` command remains supported for webhook-style ingestion.
- [ ] Tests cover: single subject, multi-subject, already-finalized, missing identity, and dry-run.

## Non-Goals

- Removing `ingest-event` webhook support.
- Changing subject-extraction regex for webhook payloads.
- Adding bulk/batch flags to individual `work-item` commands (sweep orchestrates loops).

## Notes

- Identity guard unchanged: any command receiving an unknown `--id` must fail explicitly.
- Story 225 (all-linked-PRs policy) must be implemented before `refresh-state` is complete.
