## Statement

As an automation user, I want the ability to run `backlog scan --generate-evidence` to create evidence records for resolved work items so that evidence linking is automated and audit trails are complete.

## Context

Phases A-B provide read-only scanning and reporting. Phase C adds evidence generation as an optional mode. This separation ensures:
- Scan results can be reviewed before any writes occur
- Evidence generation can be independently tested
- Workflows can generate reports without side effects, then decide whether to apply evidence

## Goals

- Add `--generate-evidence` flag to `backlog scan` command
- Implement evidence record creation logic
- Link evidence records to work items
- Preserve report structure when generating evidence
- Maintain idempotency (re-running with same event creates no duplicates)

## Evidence Record Schema

```yaml
---
type: record
subtype: evidence
id: "record-{timestamp}-{work-item-id}"
relatedWorkItem: "work-item:{id}"
sourceEvent:
  type: "workflow_run" | "pull_request"
  eventId: string
  timestamp: string
resolutionStrategy: string # e.g., "linked_pull_requests"
conditions:
  pr_link_found: true
  pr_merged: true
  workflow_succeeded: true
  subject_resolved: true
linkedAt: string # ISO 8601
---

## Event Details

[Contents: PR details, workflow run status, conditions met, resolver strategy used]
```

## Configuration

- Add optional `automation.generateEvidenceDuringScan` to `.doc-vader/backlog-consumer.json`
- Defaults to false (users explicitly opt-in)
