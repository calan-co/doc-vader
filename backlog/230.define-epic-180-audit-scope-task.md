## Summary

Define the exact Epic 180 audit boundaries, categorization rules, and overlap-review criteria before the staging migration work starts.

## Background

Epic 180 depends on a clean distinction between scripts that must migrate into core TypeScript, scripts already subsumed by Epic 170, and scripts that should become archived compatibility artifacts.

## Goals

- Fix the audit scope for `staging/`, `staging/scripts/`, and related schema assets
- Standardize categories for migrate, archive, and retain-as-shim outcomes
- Prevent the Epic 180 audit from drifting while RC work is in flight

## Deliverables

- Audit rubric covering files, categories, and overlap checks
- Categorization criteria with examples for each outcome
- Explicit guidance for Epic 170 overlap handling

## Tasks

- [x] Define the folders and file classes in scope for Epic 180 audit work
- [x] Specify the audit categories and decision rules
- [x] Document how overlap with Epic 170 affects migration or archival decisions

## Acceptance Criteria

- [x] Audit scope is documented for staging scripts and related schema assets
- [x] Categorization rules include migrate, archive, and compatibility outcomes
- [x] Epic 170 overlap checks are defined before WI-181 audit execution starts
