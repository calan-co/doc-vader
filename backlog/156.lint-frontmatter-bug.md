## Problem

The documentation linting process does not treat frontmatter schema validation failures as blocking errors. The summary reports "All documentation validation PASSED" even when frontmatter errors are present, which can lead to undetected compliance issues.

## Steps to Reproduce

1. Introduce a frontmatter schema error in a documentation file (e.g., remove a required field).
2. Run `npm run docs:lint`.
3. Observe that the summary reports success, but detailed output lists frontmatter errors.

## Expected Behavior

- The linting process should fail (non-zero exit code) and clearly report failure in the summary if any frontmatter schema errors are present.

## Actual Behavior

- The summary reports success even when frontmatter errors are present.

## Impact

- Schema compliance issues may go unnoticed, leading to invalid documentation in the repository.

## Acceptance Criteria

- [x] Linting fails with a clear error if any frontmatter schema errors are detected.
- [x] The summary accurately reflects the presence of frontmatter errors.
- [x] Exit code is non-zero on schema validation failure.
