## Statement

As a developer, I want to implement the core scan infrastructure (parser, executor, reporter) and expose a read-only `backlog scan` command so that I can test the scanning pipeline and generate structured reports before adding evidence generation logic.

## Context

Current backlog automation is embedded in workflow Python; event parsing and condition checking are implicit. Phase A extracts this into a reusable, testable CLI command that produces structured reports without making any changes to work items or backlog state.

## Goals

- Define `ParsedEvent`, `ScanState`, `ScanReport` types
- Implement `BacklogScanExecutor` (basic event parsing + condition checking)
- Implement `ScanReporter` (JSON and text output)
- Add `backlog scan` CLI command
- Generate structured reports with all conditions and errors
- Maintain backward compatibility (no behavior change from current automation)

## Tasks

- [ ] Define core types: `ParsedEvent`, `ParsedWorkflowRun`, `PRIdentity`, `WorkflowRunIdentity`
- [ ] Define `ScanState` and `ConditionEvaluation` types
- [ ] Define `ScanError` and `ScanReport` types
- [ ] Implement `BacklogScanExecutor` with basic workflow parsing (GitHub hardcoded for now)
- [ ] Implement condition evaluation: `pr_link_found`, `pr_merged`, `workflow_succeeded`, `valid_status`
- [ ] Implement `ScanReporter` with JSON output (human-readable text in Phase B)
- [ ] Add `backlog scan` command to CLI with flags: `--report-format`, `--debug`
- [ ] Parse `.doc-vader/backlog-consumer.json` for automation settings
- [ ] Unit tests for executor and reporter (mock events)
- [ ] Integration test: invoke CLI with test fixtures
- [ ] Documentation: CLI reference, example outputs, troubleshooting

## Acceptance Criteria

- [ ] `backlog scan` command produces valid JSON report
- [ ] Report includes all condition evaluations (true/false)
- [ ] Report includes all detected errors with codes and messages
- [ ] Report includes event metadata (id, type, timestamp)
- [ ] Report includes summary (total events, successes, failures)
- [ ] Command exits with code 0 (read-only; no validation failures)
- [ ] Unit tests cover all executor code paths
- [ ] No GitHub-specific code mixed into domain layer (placeholder for Phase B provider abstraction)
- [ ] Example: templ.js workflow run 25519076107 scanned and reported with current condition state
