## statement

As an architect, I want to extract vendor-specific logic into a `BacklogAutomationProvider` interface and implement a multi-strategy `SubjectResolverChain` so that the domain layer is vendor-agnostic and subject resolution is robust with fallback strategies.

## Context

Phase A implemented the scan pipeline with GitHub-specific event parsing hardcoded into the executor. Phase B abstracts this by:

1. Defining `BacklogAutomationProvider` interface for vendor-specific operations
2. Extracting GitHub logic into `GitHubBacklogAutomationProvider`
3. Implementing `SubjectResolver` interface and strategies
4. Adding `LinkedPullRequestsResolver` that fetches PR metadata via provider

## Goals

- Define `BacklogAutomationProvider` interface
- Implement `GitHubBacklogAutomationProvider`
- Define `SubjectResolver` and `SubjectResolverChain` interfaces
- Implement `PayloadSubjectTokensResolver` (current behavior)
- Implement `LinkedPullRequestsResolver` (PR metadata fallback)
- Update `BacklogScanExecutor` to use provider and resolver chain
- Add full condition taxonomy to scan report
- Structured error reporting for resolver failures
