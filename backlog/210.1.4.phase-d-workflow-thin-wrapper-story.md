## Statement

As a DevOps engineer, I want to refactor the backlog automation workflow to call the `backlog scan` CLI command instead of embedded Python so that the automation logic is versioned with the package, testable, and maintainable.

## Context

Current `.github/workflows/backlog-sweep.yml` contains embedded Python script that handles PR eligibility scanning and ingest orchestration. This makes it:

- Hard to test (Python logic is only testable in Actions)
- Hard to version (script logic is not versioned with package)
- Hard to reuse (logic cannot be invoked from other workflows or CI systems)

Phase D converts the workflow to a thin wrapper that invokes `doc-vader backlog scan` and stores the report artifact.

## Goals

- Replace embedded Python with `doc-vader backlog scan --generate-evidence` call
- Store JSON scan report as workflow artifact
- Maintain backward compatibility (same behavior as before)
- Enable audit trail via artifact storage
- Simplify workflow maintenance

## Workflow Changes

**Before**:

```yaml
- name: Scan backlog for PRs to evidence
  run: python scripts/sweep.py --repo templjs/templ.js --generate-evidence
```

**After**:

```yaml
- name: Scan backlog for PRs to evidence
  run: doc-vader backlog scan --generate-evidence --output-format json > /tmp/scan-report.json

- name: Upload scan report
  uses: actions/upload-artifact@v4
  with:
    name: backlog-scan-report-${{ github.run_id }}
    path: /tmp/scan-report.json
```

## Notes

Phase D is a refactoring with no behavior changes. It simply moves the orchestration logic from workflow Python to the CLI. This unblocks Phase E (configuration) and sets the stage for future extensions (e.g., scheduled scans, multiple forge support).

The workflow now produces structured artifacts that can be parsed for metrics, alerts, and dashboards in future work.
