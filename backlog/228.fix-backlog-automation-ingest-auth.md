## Problem

`backlog-automation.yml` triggers `backlog-ingest-pull-request.yml` and `backlog-ingest-workflow-run.yml` after successful CI runs, but the reusable ingest workflows commit with `GITHUB_TOKEN` instead of the doc-vader GitHub App token. On protected `staging`, the commit step fails with `GH013: Repository rule violations found for refs/heads/staging`.

## Goal

Make both ingest workflows authenticate with the doc-vader GitHub App token so backlog updates can be committed directly to `staging` under the existing ruleset bypass.

## Steps to Reproduce

1. Trigger `CI` on a branch that produces backlog updates.
2. Let `backlog-automation.yml` receive the `workflow_run.completed` event.
3. Observe the `Commit backlog changes` step fail with `GH013`.

## Expected Behavior

The ingest workflows should use the GitHub App installation token and successfully push backlog updates to `staging` without violating branch rulesets.

## Acceptance Criteria

- [ ] `backlog-automation.yml` passes app credentials through to both ingest reusable workflows.
- [ ] `backlog-ingest-pull-request.yml` and `backlog-ingest-workflow-run.yml` use the doc-vader GitHub App token for checkout and push operations when provided.
- [ ] A rerun of workflow `25946296093` (or an equivalent `workflow_run` event) completes successfully without `GH013`.
- [ ] The backlog automation flow still works when app credentials are present and does not broaden push access.

## Notes

- The `staging` rulesets already list doc-vader app ID `3558979` as a bypass actor.
- The failure is caused by auth identity mismatch, not by the ruleset configuration itself.
