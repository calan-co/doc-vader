## Summary

Implement the profile-aware schema-routing and selection slice required to make multi-framework validation usable in RC.

## Background

The governance and backlog validation layers have partial profile support, but they do not yet route schema and validation behavior across multiple selected documentation frameworks.

## Goals

- Support profile-driven schema-routing for multi-framework validation
- Add CLI input handling for selecting one or more active profiles
- Provide a stable input contract for the reconciliation core

## Deliverables

- Profile-selection behavior for validation entrypoints
- Schema-routing logic for multi-profile validation
- Output or trace data needed by reconciliation and CI consumers

## Tasks

1. Implement CLI and API inputs for selecting one or more profiles
2. Route validation through profile-aware schema resolution
3. Expose the selected-profile and schema-routing outcome for downstream reporting

## Acceptance Criteria

- [ ] Validation supports selecting one or more documentation framework profiles
- [ ] Schema-routing is profile-aware and deterministic
- [ ] Selected profiles and routing outcomes are available to downstream consumers
