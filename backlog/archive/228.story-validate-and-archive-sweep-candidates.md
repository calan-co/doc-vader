## Problem

The current sweep process focuses on discovery and evidence generation, but it does not consistently
pick up work items that are already `ready-for-review` or `closed` and should be validated, archived,
or reported as discrepant. As a result, valid items can remain stranded outside the archive and
invalid items can keep their stale status without a clear remediation path.

## Goal

Add a sweep pass that targets `ready-for-review` and `closed` work items, validates each candidate
against the finalization/archive policy, archives valid items, and emits a discrepancy report for
invalid items. When validation fails, the sweep should optionally update the invalid item status based
on either consumer config or an explicit run override.

## Proposed Behavior

1. Discover candidate work items with status `ready-for-review` or `closed`.
2. Validate each candidate against the archive/finalization policy.
3. Archive items that pass validation.
4. Generate a discrepancy report for items that fail validation.
5. Optionally update invalid item status when configured to do so.
6. Allow a direct run override to take precedence over consumer config.

## Configuration Proposal

Propose a consumer-config setting under `automation` for invalid-item handling, such as a target
status or disabled mode, plus a matching CLI/run override. The override should win when both are
present.

## Acceptance Criteria

- [x] Sweep identifies `ready-for-review` and `closed` work items that are eligible for validation.
- [x] Valid items are archived after validation succeeds.
- [x] Invalid items produce a discrepancy report that lists the mismatched fields or policy failures.
- [x] Invalid-item status updates can be controlled from `.doc-vader/backlog-consumer.json`.
- [x] A direct run override can supersede the config setting for invalid-item status handling.
- [x] Invalid status updates are optional and do not block report generation.
- [x] Validation, archive, and discrepancy-report paths are covered by tests.
