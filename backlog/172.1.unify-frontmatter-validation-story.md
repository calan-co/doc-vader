## Statement

As a maintainer, I want frontmatter validation to run inside remark so that schema errors are reported consistently with other rules.

## Context

Legacy validators run outside unified, causing drift and different error formats.

## Actors

- Primary: maintainers and contributors

## Goals

- Schema validation parity and consistent messages

## Preconditions

- [x] Ajv configured and schema directory known

## Steps

1. Implement plugin with Ajv cache (keyed by path + mtime)
2. Add STRICT_FRONTMATTER toggle logic
3. Replace CLI usage and capture snapshots for parity

## Outcomes

- Single-pass schema checks in remark

## Acceptance Criteria

- [x] Plugin reports missing/invalid fields per schema
- [x] Parity snapshots reviewed and deltas documented

## Notes

- Parity deltas are captured in `lib/plugins/tests/remark-frontmatter-schema.test.ts`,
  including resolver behavior for remote `$refs` and processor-integration coverage.

## Parity Snapshot

- Legacy path: external frontmatter validation scripts
- Unified path: `remark-frontmatter-schema` in `createTiabProcessor`
- Delta: schema resolver failures are surfaced as `[frontmatter-schema]` messages
  instead of crashing the lint pipeline
- Delta: processor wiring now supports explicit schema options and lint severity
  selection through `frontmatterSchema`

## Tasks

- [x] Wire `remarkFrontmatterSchema` into `createTiabProcessor` via `frontmatterSchema` option
- [x] Write and pass test suite covering plugin behavior
