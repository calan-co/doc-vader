# Doc-Pack Artifact Inventory

This is the Phase 1 inventory for the domain-pack migration. It records the
current repository-root assets without moving them or changing any consumer.
`doc-pack` is a catalog contract only: this inventory is not a discovery list,
activation configuration, or runtime loading plan.

## Inventory convention

Each row covers **every file** matched by its repository-relative path pattern.
The logical ID is generated by replacing `{path}` with that file's complete
relative path below the row root, retaining its extension. This makes the map
lossless while avoiding a second, manually maintained copy of each directory.
The logical reference format is `<owner>:<artifact-id>`.

| Current built-in artifact path | Proposed owner | Logical artifact ID | Consumers and dependencies |
| --- | --- | --- | --- |
| `schemas/doc-vader/{config.json,document-type-pack.json,doc-pack.json}` | `core` | `metadata-model/{path}` | Config loading and document-type contribution validation; draft-2020-12. |
| `schemas/metadata/base.json` | `core` | `metadata-model/base.json` | Canonical metadata route schemas. |
| `schemas/frontmatter/**/*.json` | `core` | `compatibility-metadata/{path}` | Frontmatter adapters, audit, synthesis, and work-item validation. |
| `schemas/work-management/**/*.json` | `sdlc-core` | `metadata-model/{path}` | Work-management, PRD, backlog synthesis, and terminal metadata. |

The `templates/README.md`, `templates/template-mapping.md`, `contexts/README.md`,
and `schemas/README.md` files are repository documentation, not pack runtime
artifacts. Their relocation is deferred until the owning pack documentation is
migrated.

## Extension, test, and fixture convention

`extensions` is declarative. An embedded declaration stays opaque to the
registry; a referenced declaration supplies an opaque `ref`. The registry
validates declaration shape and resolves a declared reference, but never loads
or executes it. A runtime host must obtain explicit user consent before it
activates executable behavior.

Third-party packs and extensions are not reviewed, endorsed, sandboxed, or
guaranteed by Doc-Vader. Enable only sources that you trust.

A migrated pack owns its tests and fixtures in its own pack directory. Its
manifest lists opaque references in `tests` and `fixtures`; root tests cover
only registry behavior, cross-pack dependencies, and repository consumers.
Phase verification records the required contract files and does not discover,
source, or execute pack material.
